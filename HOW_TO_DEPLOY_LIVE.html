How to Deploy Live — Step-by-Step Guide

— Overview

What "Going Live" Means

You'll deploy each part to a separate free/cheap service, then connect them together.

— Step 1 of 3

Deploy the Database (Neon.tech — Free)

1

Create a Neon account

Go to neon.tech → Sign up with your GitHub account.

2

Create a new project

Click "New Project" → Name it resume-redefined → Choose region closest to your users → Click "Create Project".

3

Copy your connection string

On the project dashboard, you'll see a connection string that looks like:

postgresql://username:password@ep-cool-name-12345.ap-southeast-1.aws.neon.tech/neondb?sslmode=require

Copy this entire string — you'll need it for the backend deployment.

Important: Keep this connection string private. Anyone with it can access your database.
4

Push the database schema

On your Mac, set the Neon connection string and push the schema:

cd ~/Desktop/ResumeMac

# Replace with YOUR Neon connection string:
DATABASE_URL="postgresql://username:password@ep-cool-name-12345.ap-southeast-1.aws.neon.tech/neondb?sslmode=require" \
pnpm --filter @workspace/db run push

You should see confirmation that the users and resumes tables were created.

— Step 2 of 3

Deploy the Backend (Railway — ~$5/month)

5

Create a Railway account

Go to railway.app → Sign up with GitHub.

6

Create a new project

Click "New Project" → "Deploy from GitHub repo" → Select Sandeep221100/ResumeMac.

7

Configure the service

Railway will detect the repo. You need to set the root directory to artifacts/api-server:

In Railway dashboard → Your service → Settings → Source → Set Root Directory to:

artifacts/api-server
8

Add environment variables

In Railway → Your service → Variables tab → Add these:

VariableValue
PORT5000
NODE_ENVproduction
JWT_SECRETA long random string (generate below)
DATABASE_URLYour Neon connection string from Step 3
FRONTEND_URLhttps://resume-redefined.vercel.app (you'll set this after Step 3)

Generate a strong JWT secret:

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

Copy the output and paste it as the JWT_SECRET value.

9

Add a build command

In Railway → Settings → Build → Set:

Build Command: pnpm install --filter @workspace/api-server... --filter @workspace/db... && pnpm --filter @workspace/api-server run build
Start Command: node --enable-source-maps ./dist/index.mjs
Railway will auto-detect the package.json and install dependencies. The build command ensures workspace dependencies (like @workspace/db) are installed too.
10

Get your backend URL

Once deployed, go to Settings → Networking → Generate Domain. Railway gives you a URL like:

https://resume-redefined-production.up.railway.app

Copy this URL — you'll need it for the frontend.

✅ Your backend is now live! Test it: visit https://your-railway-url.up.railway.app/api/auth/me — you should see a 401 unauthorized response (that's correct, it means the server is running).

— Step 3 of 3

Deploy the Frontend (Vercel — Free)

11

Create a Vercel account

Go to vercel.com → Sign up with GitHub.

12

Import your repo

Click "Add New → Project" → Import Sandeep221100/ResumeMac.

Vercel will detect it's a monorepo. Set the Root Directory to:

artifacts/job-application-master-profile

Framework should auto-detect as Vite.

13

Update the API proxy

The frontend currently proxies /api to localhost:5000 (for local dev). For production, you need to point it to your Railway backend.

Option A — Environment variable (recommended):

Edit artifacts/job-application-master-profile/vite.config.ts and change the proxy target to use an environment variable:

proxy: {
  '/api': {
    target: process.env.VITE_API_URL ?? 'http://localhost:5000',
    changeOrigin: true,
  },
},

Then in Vercel → Your project → Settings → Environment Variables → Add:

VariableValue
VITE_API_URLYour Railway backend URL (from Step 10)

Option B — Direct API calls (simpler):

Edit artifacts/job-application-master-profile/src/lib/api.ts — change the base URL:

const API_BASE = import.meta.env.VITE_API_URL ?? '';

// Then use API_BASE + '/api/auth/me' instead of '/api/auth/me'
Option B is simpler for production because the Vite proxy only works during dev. In production, the frontend is static and needs to call the backend URL directly.
14

Deploy

Click "Deploy". Vercel will build and host your frontend. You'll get a URL like:

https://resume-redefined.vercel.app
✅ Your app is now LIVE! Visit the URL in your browser, sign up, and create a resume.
15

Set FRONTEND_URL on Railway

Go back to Railway → Variables → Set FRONTEND_URL to your Vercel URL:

https://resume-redefined.vercel.app

This allows the backend to accept CORS requests from your frontend domain.

— Alternatives

Other Hosting Options

Render (Free backend, but sleeps)

Instead of Railway, use Render.com:

  • Create a Web Service → Connect GitHub repo
  • Root directory: artifacts/api-server
  • Build command: pnpm install && pnpm run build
  • Start command: node --enable-source-maps ./dist/index.mjs
  • Free tier: server sleeps after 15 min of inactivity (30s cold start)

Fly.io (Global edge hosting)

Fly.io runs your backend on servers close to your users. Free tier includes 3 shared VMs.

Supabase (Database + Auth)

Supabase offers free PostgreSQL (500 MB) plus built-in auth. Could replace both Neon and the custom auth system.

— Troubleshooting

Common Deployment Issues

CORS errors in browser console

The backend's FRONTEND_URL doesn't match your frontend URL. Update the Railway/Render variable to exactly match your Vercel URL (including https://).

API calls return 404 or fail

The frontend is trying to call localhost:5000 instead of your live backend. Make sure you set the VITE_API_URL environment variable in Vercel and redeploy.

Database connection errors

Check that your DATABASE_URL in Railway/Render exactly matches the Neon connection string (including ?sslmode=require at the end).

Build fails on Railway/Vercel

Check the build logs in the dashboard. Common issues:

  • Wrong root directory setting
  • Missing environment variable
  • pnpm version mismatch (add packageManager to root package.json)

Login/signup doesn't work

Make sure JWT_SECRET is set on the backend. Generate one with:

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
